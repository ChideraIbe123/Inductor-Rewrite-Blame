Subject: [CS598APE Midterm] Which Rewrite Made My Model Slower? (Chidera Ibe)

Project: Finding and blaming bad graph rewrites in TorchInductor.
Code: rewrite_blame/ (Python package, CLI), tests/, results/ in the project repo.

1. WHAT IS BUILT
----------------
Everything below runs end to end from a command line and is covered by 100
automated tests (65 unit, 35 that compile graphs with Inductor), all passing
on two machines: my laptop (Apple M4 Pro, 8 threads) and the course VM
(4-core Xeon, AVX-512, oneDNN). No GPU was available on either machine, so all
measurements use Inductor's CPU C++/OpenMP backend; the rewrite passes under
study are the same on GPU, and the code parser already handles Triton output.

(a) Rewrite switches (proposal item 1). TorchInductor applies most rewrites
    through a generic PatternMatcherPass; each rule is applied only if its
    extra_check(match) hook returns true. My tool wraps that hook on every
    rule, so each rule can be switched off without modifying PyTorch, and the
    harness records how often each rule fired or was suppressed. Discovery
    finds 227 pattern rules on the Mac build and 354 on the x86 build (oneDNN
    adds conv/linear fusion rules), plus 26 config flags and 16 opt-in passes.
    A "state" is the set of switches that are on; "default" is stock Inductor.

(b) Measurement harness (item 2). One configuration = one subprocess that
    compiles the model, captures the generated wrapper code, and records:
    fused-kernel count and names, extern/fallback calls (BLAS, flash
    attention, oneDNN), bytes of intermediate buffers allocated, static
    load/store sites, Inductor's own metrics, which rules fired, a post-grad
    op histogram, correctness vs. eager (allclose 1e-3), and timing (10
    warm-up calls, 5x10 timed calls, median and MAD). Results are cached in
    SQLite by (model, machine, state hash, protocol), so nothing is measured
    twice. Noise threshold: the baseline is run in 7 separate processes and
    tau = max(3*MAD of the medians, 1% of the median). Measured tau is 1.2-5.5%
    depending on the model.

(c) Attribution tool (item 5, first version). Input: a fast state F and a
    slow state S. Candidates are the signed differences (+rule = turned on,
    -rule = turned off), so both "a new rewrite hurt" and "a helpful rewrite
    was lost" are covered. Zeller's ddmin runs over the candidates with a
    timing judge (slow iff median exceeds the fast reference by more than
    tau; borderline cases are re-measured). Output: a 1-minimal culprit set, a
    pair check (does each culprit hurt alone?), and the kernel-level diff
    between F and F+culprits. A second judge uses deterministic compile-time
    metrics (kernel count, allocated bytes) for noise-free tests.

(d) Corpus (item 1). 24 models: 6 hand-written graphs that each plant one
    rewrite family (manual attention, conv-bn-relu, split/cat, layer-norm MLP
    with a pointless dtype round trip and 1/sqrt, a decode-shaped MLP,
    cat/slice chains); 6 torchvision models; 12 HuggingFace configs (BERT,
    DistilBERT, GPT-2 prefill/decode, T5 encoder, SmolLM-135M and Qwen2.5-0.5B
    prefill/decode), built from configs with random weights (no downloads).

Two things I had to discover the hard way: a hit in Inductor's FX-graph cache
skips every pass and hides which rules fired, so the harness disables that
cache during measurement (C++ kernels are still cached by source hash); and
calling Inductor's lazy pattern initialisers directly poisons their
functools.cache keys and causes "duplicate pattern" errors, so discovery goes
through a real warm-up compile.

2. TESTING (item 3)
-------------------
Unit tests (no compilation, <1 s): ddmin on synthetic cost models (single
culprit, pair-only culprit flagged as an interaction, two independent
culprits -> 1-minimal result, three-way interaction, a masking rewrite that
speeds things up, a noisy judge, 25 random cost models checked for "slow and
1-minimal", logarithmic judge-call count: a culprit among 256 changes found in
<= 40 evaluations); the code parser on hand-written C++ and Triton wrapper
fixtures with known kernel/pointer/load/store/extern/allocation counts; the
noise threshold; the store; the timing judge's re-measure band.

Inductor tests (compile small graphs): for every planted toy graph the
expected rule fires by default, its switch suppresses it, the post-grad graph
changes in the predicted way (rsqrt becomes sqrt+reciprocal; the dtype round
trip survives without pointless_convert; flash attention disappears and two
bmm calls plus a softmax kernel appear without the attention rules;
decompose_mm_pass removes the mm calls; freezing folds batch-norm into the
conv), and outputs match eager under both states. Pipeline tests cover
subprocess isolation, cache hits, failure reporting, registry determinism
across processes, and attribution recovering planted culprits with the
metric judge.

Medium/large programs: BERT-base, GPT-2 small, ResNet-18 (Mac) and the toy
graphs on both machines have been through the full noise -> verify -> sweep ->
attribute pipeline. ResNet-50, SmolLM-135M, GPT-2 and BERT are running on the
VM now (4 cores, so slow); ViT-B/16 and Qwen2.5-0.5B are registered but not
yet measured.

3. PRELIMINARY RESULTS
----------------------
Switch verification (toggle each candidate, compare the compiled program):
of ~45 candidates per model, only 4-8 change the program at all; the rest are
no-ops for that model. Pattern rules that never fired cannot matter, so the
attribution universe per model is short.

Leave-one-out timing sweeps (median time vs. default, beyond tau):
  model                 machine  effect
  attention_block       Mac      all pattern rules off: +33%  (loses SDPA)
  attention_block       VM       all pattern rules off: -10.6% (FASTER!)
  decode_mlp (1 token)  Mac      opt-in decompose_mm_pass on: +15% slower
  resnet18              Mac      layout_optimization off: +11%
  bert_base (eager attn) Mac     _sfdp_pattern_28 off: +4.5%
  norm_mlp              Mac      inplace_buffers off: +4.3%; constant folding
                                 off: +2.6%
  norm_mlp              VM       freezing on (oneDNN prepack): -47%
  gpt2_prefill          Mac      nothing beyond noise (already uses SDPA)

Attribution case studies (timing judge, measured tau):
  * attention_block, Mac: fast = default, slow = all 63 inference attention
    rules off (+36%). 16 judge evaluations (vs 63 leave-one-out, 1953 pairs).
    Verdict: INTERACTION of _sfdp_pattern_11 and _sfdp_pattern_12; neither
    reproduces the slowdown alone, because rule 12 matches the same graph when
    11 is disabled. Kernel diff: 1 fused kernel + 1 flash-attention call ->
    4 fused kernels + 2 bmm calls; intermediate bytes 4.2 MB -> 11.6 MB.
    A one-at-a-time sweep would have blamed nothing.
  * attention_block, VM: the roles flip. fast = no fusion, slow = default
    (+8.4%). 8 evaluations. Verdict: single culprit +_sfdp_pattern_11. Same
    rewrite, opposite sign on different hardware: the fused CPU
    flash-attention kernel loses to bmm + fused softmax on this Xeon.
  * decode_mlp, Mac: fast = default, slow = all 16 opt-in passes on (+14%).
    7 evaluations. Single culprit: +decompose_mm_pass (3 BLAS calls replaced
    by one fused kernel with 4x the load sites).
  * resnet18, Mac: six flags changed, +11%. 5 evaluations. Single culprit:
    -layout_optimization (channels-last lost; 14 -> 12 kernels).
  * norm_mlp, Mac: eight flags changed, +3.6%. Culprit: -constant_folding.
    The sweep shows a second independent cause (inplace_buffers); ddmin
    returns a 1-minimal set, not every cause. Planned fix: iterate with found
    culprits moved into the fast state until the residual is within noise.
All attributions took under 3 minutes; all compiled outputs matched eager.
